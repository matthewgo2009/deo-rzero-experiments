## Problem 1 — the 4B base model ignores the assigned operator ~62% of the time

`mismatch ≈ 6,250 / 10,000` proposals per iteration: the model emits `<strategy>X</strategy>`
with X ≠ assigned action, despite the dedicated system prompt ("operator selected externally,
you MUST execute exactly that strategy") and the user message pinning the letter.

Per the review's required fix, every mismatch is (a) recorded as a bandit failure for the
CHOSEN action and (b) dropped before scoring/MH. Consequences:

- **The chain is starved.** Effective proposals reaching MH ≈ 10,000 − 6,250 (mismatch)
  − 1,538 (surface-invalid) ≈ 2,200/iter — roughly 1/4 of the uniform arm's throughput
  (V1 arm rejects only parse-failures). MCMC mixing is proportionally slower.
- **MATH-500 lags the uniform arm** so far: 74.8 / 76.6 (iters 1–2) vs icy_sprout's 78.2 / 75.4.
- Upload counts are similar (~1,100 vs ~1,230), so the *pool* is not collapsing — the walk is
  just moving less per iteration.

## Problem 2 — bandit reward too sparse to learn: all action means ≈ 0.04

Success rate = 400–460 / 10,000 ≈ 4–5% overall. Two compounding causes:

1. Mismatch (62%) and surface-invalid (15%) are booked as failures for the chosen arm,
   so ~77% of every arm's pulls are failures for reasons largely UNRELATED to the arm's
   mathematical usefulness — compliance failure is mostly a property of the base model's
   instruction following, roughly uniform across actions.
2. Conditional on reaching scoring (~2,200), success ≈ 400/2,200 ≈ 18%, and the strict
   Novel(cluster ≤ 1) + Trainable-context "r_unc must not degrade by > ε" conditions
   thin it further.

Result: posterior means are flat (0.03–0.05, spread ≈ noise), Thompson sampling stays
near-uniform, and the bandit adds compliance-rejection cost without any learned steering.
On current trajectory the bandit arm will finish ≤ uniform.

## Diagnosis

The strict operator-compliance rule (review fix #1) is CORRECT for attribution but
interacts catastrophically with a small base model's low instruction-following:
attribution noise was traded for a 4× throughput cut and a reward signal dominated by
compliance noise. The bandit is mostly learning "how often does Qwen3-4B-Base obey
strategy X" (≈ uniformly badly), not "which mutation works for this context".

## Candidate fixes (for discussion)

**(a) Credit the EXECUTED strategy instead of dropping mismatches.**
On mismatch, keep the proposal, let it be scored / MH-judged, and record the outcome
under (context, ACTUAL emitted strategy). Attribution stays truthful (the proposal WAS
generated by K_actual); throughput is restored; the bandit still steers because the
prompt shifts the action distribution even at 38% compliance (P(execute=a | assigned=a)
≫ P(execute=a | assigned=b)). Cost: the bandit's lever is soft — it selects an
"intention", the realized kernel is a compliance-weighted mixture. The TS policy then
optimizes over intentions, which is still well-defined.

**(b) Keep strict compliance but resample on mismatch (retry ≤ R times).**
Restores purity of K_a at ~1.6–2.6× mutation-LLM cost (62% mismatch ⇒ expected retries).
Simple, but GPU cost scales and residual mismatches still need policy (a) or dropping.

**(c) Constrained decoding / prefill.** Force the output to begin with
`<strategy>{assigned}</strategy>` via prompt prefilling (completion API: append the tag
to the prompt itself so the model continues from it). Compliance becomes ~100% by
construction; mismatch class disappears entirely. Cheapest and most surgical — the tag
is no longer a model choice. Risk: the model may still *semantically* execute a different
transformation than the tag claims (tag-conditioned, not tag-verified); a lightweight
post-hoc strategy classifier would be needed to audit true execution rates.

**(d) Reward shaping.** Exclude compliance/parse failures from the bandit ledger
entirely (record only scored proposals), so arm means reflect mathematical usefulness;
combine with (a) or (c) for throughput.

**(e) Bigger mutator.** 8B (or the current solver instead of base) as mutation LLM —
compliance likely improves substantially; changes the proposal distribution q(x'|x).

My recommendation: **(c) prefill the strategy tag** + **(d) ledger only scored proposals**,
which kills both problems at near-zero cost, with a small audit sample to estimate
tag-vs-actual execution divergence. Fallback: (a).

## Open questions for the reviewer

1. Is intention-level credit (a) acceptable for the Thompson-sampling formulation, i.e.
   bandit over "assigned action" with a compliance-weighted realized kernel? (The paper's
   K_a assumes faithful execution.)
2. With prefill (c), the `<strategy>` tag is no longer evidence of execution. Is a
   sampled audit (classifier or LLM judge on ~100 proposals/iter) sufficient, or should
   every proposal be verified?
3. Should Novel() use cluster ≤ 1 (strict) or allow small clusters (≤ 2–3)? At 2000-q
   pools the strict rule contributes to reward sparsity.
4. Success ≈ 18% even conditional on scoring — is the Trainable-context ε-non-degradation
   condition (eps=0.1) too tight on top of the in-band requirement?
